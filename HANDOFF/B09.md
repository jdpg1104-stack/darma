# B09 · Encuestas del feed

## Objetivo

Una encuesta ligera intercalada en el feed responde a la pregunta que más se hace
en Darma: «¿le pasa a alguien más?». Este bloque construye ese formato: un banco
curado de preguntas de bienestar, una cadencia por persona para que aparezcan
cuando aportan y no cuando saturan, un voto por persona forzado por la clave
primaria de la base, y resultados agregados en vivo que **nunca** revelan quién
votó qué. El banco se repone solo, porque una encuesta caducada en el feed es
peor que ninguna encuesta.

## Qué construir

1. **Migración `0009_b09_encuestas.sql`.** `polls`/`poll_options`/`poll_votes` ya
   existen; falta el banco, la cadencia y la privacidad del agregado:

   ```sql
   -- De dónde salió la encuesta y con qué clave del banco, para no repetirla.
   alter table public.polls add column origin text not null default 'usuario'
     check (origin in ('usuario', 'banco'));
   alter table public.polls add column bank_key text;
   create unique index uq_polls_bank_key on public.polls (bank_key) where bank_key is not null;

   -- Banco curado. En tabla y no en constante de TS para poder retirar una
   -- pregunta en producción sin desplegar: una pregunta de bienestar puede
   -- envejecer mal muy deprisa.
   create table public.poll_bank (
     key        text primary key,
     question   text not null check (char_length(question) between 5 and 200),
     options    text[] not null check (array_length(options, 1) between 2 and 5),
     topic      text,
     language   text not null default 'es' check (language ~ '^[a-z]{2}$'),
     enabled    boolean not null default true,
     -- Cuántas veces se ha activado ya. Rota por la menos usada.
     times_used smallint not null default 0,
     last_used_at timestamptz
   );
   create index idx_poll_bank_pick on public.poll_bank (language, times_used, key)
     where enabled;

   -- "No me interesa" / "ya la vi y no voté". Es lo que permite que la cadencia
   -- no dependa solo de haber votado.
   create table public.poll_dismissals (
     poll_id    uuid not null references public.polls(id) on delete cascade,
     user_id    uuid not null references public.profiles(id) on delete cascade,
     created_at timestamptz not null default now(),
     primary key (poll_id, user_id)
   );

   -- Última vez que ESTA persona vio una encuesta en el feed. Una fila por
   -- persona: la cadencia se resuelve con una lectura por PK, no agregando.
   create table public.poll_cadence (
     user_id     uuid primary key references public.profiles(id) on delete cascade,
     last_shown_at timestamptz,
     shown_today   smallint not null default 0,
     day           date not null default current_date
   );
   ```
   RLS: `poll_bank` sin políticas de lectura para `authenticated` (el banco
   completo revelaría las preguntas futuras y sesgaría las respuestas);
   `poll_dismissals` y `poll_cadence` con políticas «solo la propia fila»
   (`user_id = (select auth.uid())`) para select/insert, y `revoke update, delete`.

   Y la pieza de privacidad del agregado:
   ```sql
   -- Umbral por debajo del cual NO se publican porcentajes. Con 3 votos y un
   -- refugio de 4 personas, un porcentaje identifica a quien votó.
   alter table public.polls add column min_reveal smallint not null default 5;
   ```

2. **Perfil de sistema.** `polls.author_id` es `not null` y la política
   `polls_insert_own` exige `author_id = auth.uid()`. Las encuestas del banco no
   tienen autor humano. Solución: un perfil con alias reservado `Darma` creado por
   la migración (`insert into auth.users` no es tuyo → créalo en la migración
   **solo si B01 no lo ha hecho ya**; si no, léelo por alias) y **las inserta
   `service_role`**, que salta RLS. El id se resuelve una vez y se cachea en el
   módulo. Anota en `PEDIDOS.md` que B01 debería reservar el alias `Darma` en el
   registro para que nadie lo tome.

3. **`lib/polls/limites.ts`** — SSOT de límites, validados en cliente **y**
   servidor: pregunta 5–200 (el CHECK de `polls` manda), opción 1–80 (CHECK de
   `poll_options`), 2–5 opciones, `ordinal` 0–9. Importa estos valores en tu zod;
   no los tecleés dos veces.

4. **`lib/polls/cadencia.ts`** — decisión **pura**, sin base de datos:

   ```ts
   export const MAX_ENCUESTAS_DIA = 2
   export const HORAS_ENTRE_ENCUESTAS = 6
   /** Cada cuántas tarjetas del feed puede caer una encuesta. */
   export const CADA_N_TARJETAS = 7
   ```
   `decidirMostrar(señales, ahora)` → `{ mostrar: boolean; motivo: string }`.
   Señales: `ultimaMostradaEn`, `mostradasHoy`, `posicionEnFeed`,
   `yaVotoOMDescarto`. Los umbrales viven **solo aquí**: si los repites en la UI
   o en un comentario de otro archivo, se desincronizarán.

   Por qué una cadencia y no «una encuesta cada X posiciones»: el feed de Darma se
   lee en ráfagas cortas. Si la regla fuera solo posicional, quien abre la app
   cinco veces al día vería cinco encuestas; con el tope diario, ve dos.

5. **`lib/polls/reponer.ts`** — reposición automática. Regla: siempre debe haber
   **al menos 3 encuestas `active`** por idioma, y ninguna con más de 14 días.
   Al ejecutar: cierra (`state = 'hidden'`) las que superen la edad o cuya
   saturación (`total_votes / audiencia_estimada`) pase el umbral, y activa desde
   `poll_bank` la de menor `times_used` que no esté ya activa. Todo con
   `service_role` y `on conflict (bank_key) do nothing`: dos reposiciones
   simultáneas no pueden activar la misma pregunta dos veces.

   **Se dispara desde `POST /api/polls/reponer`** (tu prefijo; `/api/cron/*` es de
   B08). Bearer `CRON_SECRET`, `timingSafeEqual`, fail-closed. Pide a F4 en
   `PEDIDOS.md`: `{"path":"/api/polls/reponer","schedule":"41 3 * * *"}`.

6. **`GET /api/polls/siguiente?posicion=`** — devuelve la encuesta que toca a esta
   persona ahora, o `null`. Aplica `decidirMostrar`, elige entre las activas la que
   no haya votado ni descartado, y **actualiza `poll_cadence` en la misma
   petición** (upsert). Dos consultas máximo.

7. **`POST /api/polls/[id]/voto`** — body `{ opcionId }`. Inserta en `poll_votes`
   con el cliente **RLS** (la política `poll_votes_insert_own` ya exige
   `user_id = auth.uid()`); el `userId` sale de la sesión, **jamás del body**. Un
   `23505` (violación de PK) se traduce a `{ ok: false, code: 'sin_permiso',
   message: 'Ya has respondido a esta encuesta' }` — no a un 500. Devuelve los
   resultados ya actualizados en la misma respuesta: quien vota quiere ver el
   agregado en ese instante, no tras un refetch.

8. **`GET /api/polls/[id]/resultados`** — agregado desde
   `poll_options.vote_count` y `polls.total_votes`, **nunca** contando
   `poll_votes`. Si `total_votes < min_reveal`, devuelve `revelado: false` y sin
   porcentajes: con 3 votos, un porcentaje identifica a quien votó.

9. **`POST /api/polls/[id]/descartar`** — inserta en `poll_dismissals`. Es lo que
   evita que la misma encuesta persiga a alguien que no quiere responderla.

10. **`components/polls/`**: `TarjetaEncuesta.tsx` (`'use client'`, optimista al
    votar pero **revirtiendo** si el servidor rechaza), `BarraResultado.tsx`
    (server, puro), `EstadoOculto.tsx` (el «aún no hay respuestas suficientes para
    mostrar el resultado» cuando `revelado: false`). La tarjeta muestra siempre
    «Tu respuesta es anónima; ni siquiera quien preguntó puede verla» — no es
    adorno, es lo que hace que la gente responda con honestidad.

```ts
// Rutas — todas con sesión, zod y rate limit.
// GET  /api/polls/siguiente?posicion=<int>   → { ok: true, data: EncuestaFeed | null }
// POST /api/polls/[id]/voto  { opcionId }    → { ok: true, data: EncuestaFeed }
```

Reglas del contrato que **no** son negociables:

- `EncuestaFeed` **nunca** incluye la lista de votantes, ni un `userId`, ni un
  recuento por opción cuando `revelado: false`. Es la forma que consumen B02 y la
  tarjeta; si un campo no está aquí, no sale de la API.
- Voto duplicado → `sin_permiso` (403), no 409 ni 500. El mensaje es humano.
- `miVoto` sale de `poll_votes` filtrado por la **propia** política RLS
  (`poll_votes_read_own`): no lo consultes con el cliente admin «para ir más
  rápido».

## Consultas y rendimiento

Elegir la encuesta que toca (una consulta, sin `count(*)`):

```sql
select p.id, p.question, p.total_votes, p.min_reveal, p.closes_at, p.origin
  from public.polls p
 where p.state = 'active'
   and (p.closes_at is null or p.closes_at > now())
   and not exists (select 1 from public.poll_votes v      where v.poll_id = p.id and v.user_id = :yo)
   and not exists (select 1 from public.poll_dismissals d where d.poll_id = p.id and d.user_id = :yo)
 order by p.created_at desc, p.id desc
 limit 1;
```

`idx_polls_feed (created_at desc, id desc) where state = 'active'` cubre el orden;
los dos `not exists` se resuelven por PK (`(poll_id, user_id)` en ambas tablas):
una sonda por candidato. Como el pool de encuestas activas se mantiene en unas
pocas por idioma (§5), este `limit 1` toca un puñado de filas aunque haya
millones de votos.

Resultados (jamás contando `poll_votes`):

```sql
select o.id, o.ordinal, o.label, o.vote_count, p.total_votes, p.min_reveal
  from public.poll_options o
  join public.polls p on p.id = o.poll_id
 where o.poll_id = :id
 order by o.ordinal;
```

El `unique (poll_id, ordinal)` de `0002` **ya es** el índice de este acceso: no
añadas otro sobre `poll_id`. `vote_count` y `total_votes` los mantiene
`poll_votes_sync()` en el camino de escritura, que es N veces menos frecuente que
el de lectura — por eso pintar los porcentajes de una encuesta con un millón de
votos cuesta lo mismo que con diez.

Cadencia: lectura y escritura por PK sobre `poll_cadence` (`user_id`). Cero
agregación.

Presupuesto: la tarjeta añade < 8 KB de JS al bundle del feed y `GET
/api/polls/siguiente` resuelve en ≤ 2 consultas. Pega el `EXPLAIN ANALYZE` de la
consulta de selección con 1 M de `poll_votes` sembrados.

## Seguridad

- **El anonimato del voto es el producto.** `poll_votes_read_own` ya limita cada
  quien a su fila; tu API no debe abrir ni una rendija: nada de «cuántos de mis
  almas afines votaron X», nada de exportar `poll_votes`, nada de devolver
  `created_at` de votos ajenos (con pocos votantes, la marca de tiempo cruzada con
  la actividad del feed identifica a la persona).
- **Umbral de revelación** (`min_reveal`, 5 por defecto). Un agregado sobre 2
  votos no es un agregado. Sin este umbral, la primera persona que vota en una
  encuesta nueva ve «100 % opción A» y sabe qué votó la siguiente en cuanto el
  porcentaje cambia.
- `userId` **siempre** de la sesión. Aceptar un `userId` del body es la
  vulnerabilidad más común de este tipo de ruta (`CONTRATOS.md` §6).
- Cliente RLS en todo salvo en la reposición del banco, que necesita `service_role`
  para insertar con el `author_id` del perfil de sistema. Justifícalo en comentario.
- El texto libre de una encuesta creada por una persona (`origin = 'usuario'`)
  **pasa por `evaluarRiesgo()` de `lib/crisis.ts` antes de persistirse**
  (`CONTRATOS.md` §9): una pregunta puede ser una llamada de auxilio disfrazada
  («¿alguien más ha pensado en no estar?»). Si el nivel es `high`/`critical`, se
  escribe `crisis_events` y se devuelve la tarjeta de recursos **en la misma
  respuesta**. La encuesta no se borra ni se oculta: se prioriza.
- Rate limits: `siguiente` 60/min, `voto` 20/min, `descartar` 20/min, `reponer`
  2/min global. Y `poll_bank` no se expone jamás por API.

## Pruebas exigidas

1. `decidirMostrar`: con `mostradasHoy = MAX_ENCUESTAS_DIA` → `false`; con
   `ultimaMostradaEn` hace 3 h y `HORAS_ENTRE_ENCUESTAS = 6` → `false`; con
   `posicionEnFeed = 3` y `CADA_N_TARJETAS = 7` → `false`. **Camino de fallo.**
2. `decidirMostrar` es pura: mismas señales, misma salida, sin tocar el reloj real
   (el `ahora` es inyectable).
3. Voto duplicado (misma persona, misma encuesta, **otra** opción) → 403
   `sin_permiso`, y `poll_options.vote_count` **no** se incrementa. **Fallo.**
4. Voto con `opcionId` de **otra** encuesta → 422 `entrada_invalida`, sin
   revelar si esa opción existe.
5. Con `total_votes < min_reveal`, la respuesta trae `revelado: false`,
   `votos: null` y `porcentaje: null` en **todas** las opciones. **Fallo.**
6. Al superar `min_reveal`, los porcentajes suman 100 (comprueba el redondeo con
   3 opciones y 7 votos: 43/29/29 → el test fija la regla de reparto del resto).
7. `GET /api/polls/[id]/resultados` **nunca** ejecuta un `count(*)` sobre
   `poll_votes` (test sobre el SQL generado o sobre el mock del cliente).
8. Descartar una encuesta hace que `siguiente` deje de devolverla, y descartarla
   dos veces no falla (idempotente por PK).
9. Reposición: con 0 encuestas activas activa 3 del banco; ejecutarla dos veces
   seguidas **no** duplica ninguna (`uq_polls_bank_key`). Con el banco agotado
   devuelve `{ activadas: 0 }` sin error.
10. **Camino de fallo:** `POST /api/polls/reponer` sin Bearer, con Bearer erróneo
    y con `CRON_SECRET` sin definir → 401 en los tres casos.

## Trampas conocidas

1. **PK `(option_id, user_id)` en vez de `(poll_id, user_id)`.** La de `0002` es
   la correcta y ya está puesta; la trampa es *razonar* como si fuera la otra —
   por ejemplo, permitir «cambiar de opción» borrando e insertando. `0002` revoca
   `update` **y** `delete` sobre `poll_votes` justo para que eso no exista: el voto
   es definitivo. Si tu UI ofrece «cambiar respuesta», la API devolverá 403 y
   parecerá un bug.
2. **Calcular porcentajes contando `poll_votes`.** Es lo primero que sale al
   escribirlo, funciona perfecto con 20 votos y es un `Seq Scan` con 20 millones.
   Los contadores desnormalizados existen para esto.
3. **Publicar el agregado desde el primer voto.** Con N pequeño, el porcentaje es
   un canal de fuga: dos personas votando en una encuesta poco vista deducen su
   voto mutuo. `min_reveal` no es una preferencia estética.
4. **Insertar encuestas del banco con el cliente RLS.** `polls_insert_own` exige
   `author_id = auth.uid()`, y el cron no tiene sesión: fallará con cero filas y
   sin error obvio. La reposición va con `service_role` y el perfil de sistema.
5. **Saltarse `evaluarRiesgo()` porque «es solo una encuesta».** El texto de una
   pregunta escrita por una persona es texto escrito por una persona, y
   `CONTRATOS.md` §9 no hace excepciones por formato. La crisis gana siempre.
